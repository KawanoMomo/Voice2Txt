# ADR-draft: クリップボードに入れられない確定版 — 粘る場所と、入らなかったときの知らせ方

- **ステータス**: 提案(未採番)
- **カテゴリ**: architecture
- **日付**: 2026-10-07
- **対象プロジェクト**: Voice2Txt
- **関連**: 仕様 4.4(退避)、BLK-owner-20261007-0727-1

## コンテキスト

確定版はクリップボード経由で届ける。他のアプリがクリップボードを開いたままだと書き込みが失敗する。
これまでは失敗を「退避」として扱い、「Ctrl+V で貼れます」と出していたが、クリップボードには前の内容が残っているので、
Ctrl+V では別の内容が貼られ、確定版は黙って失われていた。また Win32 実装は UI スレッド上で寝ながら再試行していた。

## 検討した選択肢

1. Win32 実装の中で長く再試行する — UI スレッドが止まり、オーバーレイの描画・トレイが固まる。偽物で試せない
2. `PushToTalkController` が非同期に粘る(既定 3 秒、50 ms 間隔。Win32 実装は 1 回の呼び出しで短く試すだけ)。入らなければ専用の結末にする
3. 入らない確定版をメモリに持ち続け、次の発話のときに再び試す — 後の発話との順序と、どの確定版がどこへ届いたかが分かりにくくなる

## 決定

2 を採る。入らなかったときは結末 `Outcome.Failed`・理由 `ClipboardBusy`、オーバーレイの状態「入力失敗」
(「! 他のアプリがクリップボードを使用中のため入力できませんでした — もう一度話してください」、6 秒)を出す。「退避」とは区別し、
「Ctrl+V で貼れます」は確定版が実際にクリップボードに入ったときだけ出す。ログには理由と試行回数を書き、本文は書かない。
粘る間、後の発話は順番を待つ(追い越さない)。時間は `PttOptions` に持ち、設定項目にはしない。

## 結果

- 検証モードの台本に `lockClipboard`(ms)を足し、この経路を確かめられる
- 退避の意味は仕様 4.4 のまま(確定版はクリップボードにある)に戻る
- 3 秒を超えてクリップボードを掴み続けるアプリがあると、その発話は失われる(知らせは出る)
