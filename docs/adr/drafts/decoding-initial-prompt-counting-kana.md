# ADR-draft: 四字熟語の「いち」「ご」が数字に寄る — 初期プロンプトの数える列を「ここのつ、10。」にする

- **ステータス**: 提案(未採番)
- **カテゴリ**: architecture
- **日付**: 2026-11-03
- **対象プロジェクト**: Voice2Txt
- **関連**: decoding-initial-prompt-counting.md(「9つ、10。」を足した決定。これを改める)、BLK-transcriber-20261102-1815

## コンテキスト

四字熟語を読みどおりのかなで言った発話「いちごいちえの精神で、…」で、確定版が「151への精神で…」になった。
初期プロンプトの末尾「9つ、10。」が数字の書き方を見せるため、数え上げでない語の中の「いち」「ご」まで数字に寄る。エラーは無く、利用者は気づけない。

## 検討した選択肢

1. 「151」→「一期一会」の置換・後処理 — 届いた文字列を書き換える(置換表は増やさない)
2. 初期プロンプトから数える列を外す — 「151」は消えるが、数える列の末尾「とお」が「等」に戻る(前の ADR の理由)
3. 数える列をプロンプトの先頭に置く(「9つ、10。えーと、…」) — 「151」は消え「とお」も「10」のまま
4. 数える列を「ここのつ、10。」にする(数字は「つ」が付かない短い数「とお」だけ) — 「151」は消え「とお」も「10」のまま
5. beam search — 「151」は消えるが、数える列がかな書き(「ひとつ、ふたつ、…」)に寄る

## 決定

4 を採る(`Decoding.InitialPrompt` = `えーと、あの、ええと、その、まあ、えっと。ここのつ、10。`)。言い淀みの並びと数える列の位置は前の決定のまま変えず、
数字で見せるのを「10」だけにする(unit で守る)。かな・数字・句読点だけで 32 文字以内も変わらない。

## 結果

- large-v3-turbo(CUDA): yoji-01-r2・utt-31 が「151への」→「一期一への」。数える発話(utt-25)は「1つ、…、9つ、10。」のまま。言い淀み・長い無音・短い発話・utt-27 は同じ
- corpus の数字を含む 20 秒以下の 78 本で、変わったのは yoji-01-r2(上)、sushiki-01(「たす」→「+」、読点→句点。記号表記は許容)、
  far-01(遠い声。「1階」→「実階」。progress.md の記録は既に「実階」で NG・wontfix。「9つ」の数字寄せでたまたま「1階」になっていた。数える列を先頭に置く 3 でも「実階」)だけ
- 「会」が「への」になるのは初期プロンプトを外しても、beam search でも同じ(合成の声の「いちえ」)。プロンプトでは直らないので扱わない
- 検証モードの台本 `transcriber-3`(`utt-31.wav`)で、数字に戻ったら赤になる
