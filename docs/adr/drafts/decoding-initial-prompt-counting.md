# ADR-draft: 数える列の末尾「とお」が「等」に化ける — 初期プロンプトの末尾に「9つ、10。」を足す

- **ステータス**: 提案(未採番)
- **カテゴリ**: architecture
- **日付**: 2026-10-08
- **対象プロジェクト**: Voice2Txt
- **関連**: decoding-initial-prompt-fillers.md(初期プロンプトの元の決定)、BLK-transcriber-20261007-2351

## コンテキスト

かなで数える発話「ひとつ、ふたつ、…、ここのつ、とお。」で、確定版が「1つ、2つ、…、9つ、等。」になった。前の語は数字で書かれ、
「つ」が付かない短い数「とお」(約 0.4 秒)だけが数でない語になる。エラーは無く、利用者は気づけない。合成音声の音素は「toːo」で正しい。

## 検討した選択肢

1. 「9つ、等」→「9つ、10」の置換・後処理 — 届いた文字列を書き換える(後処理と辞書は仕様 7 章の後続)。文脈の判定を作り込むことになる
2. 初期プロンプトに「ひとつ、ふたつ、とお。」(かな) — 直るが、確定版全体がかな書きに寄る(「請求書の締め日」がひらがなになる等)
3. 初期プロンプトに「1つ、2つ、10。」 — 直るが、物音(クリック音)が「1つ、10。」になり、遠い声の「受付は」が「2つとは」になる
4. 初期プロンプトに「10。」だけ — 直らない
5. 初期プロンプトに「9つ、10。」 — 数える列の終わりだけを見せる

## 決定

5 を採る(`Decoding.InitialPrompt` = `えーと、あの、ええと、その、まあ、えっと。9つ、10。`)。かな・数字・句読点だけで 32 文字以内(unit で守る)。

## 結果

- large-v3-turbo: corpus 85 本 + tests/fixtures 24 本 + 合成の物音 4 本で、変わったのは dialect-01(「等」→「10」)、far-01(「実階」→「1階」)、
  breath-01(読点が 1 つ増える)、redo-03(「第一/第三」→「第1/第3」。数字表記は許容)だけ。物音は「はい。」のまま(元と同じ)
- large-v3: dialect-01 が「10つ」→「10」。ほかは句読点と漢数字→数字の揺れ
- base: 良くなる本と悪くなる本が混じる(「午後3時」→「5個3時」、「見つもり書」→「3つもり書」)。base は元から誤りが多く、既定は large-v3-turbo
- 検証モードの台本 `transcriber-3`(`utt-25.wav`)で、「等」に戻ったら赤になる
