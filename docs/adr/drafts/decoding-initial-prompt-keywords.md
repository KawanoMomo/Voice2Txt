# ADR-draft: カスタム語彙は engine=whisper でも、表記を初期プロンプトの前に読点でつないで渡す

- **ステータス**: 提案(未採番)
- **カテゴリ**: architecture
- **日付**: 2026-11-04
- **対象プロジェクト**: Voice2Txt
- **関連**: decoding-initial-prompt-counting.md、decoding-initial-prompt-fillers.md、decoding-initial-prompt-no-final-period.md、BLK-transcriber-20261104-1100、BLK-transcriber-20261104-0335

## コンテキスト

既定の Whisper(large-v3-turbo)は、文の途中の日常の語を同音の別の表記に当てることがある(「速達で送って」→「即達で送って」。読みをかなに合わせた音声でも同じ)。
初期プロンプトの有無・復号の方法・モデルを変えても直らない(BLK-transcriber-20261104-0335 の切り分け)。利用者が書いてほしい表記を渡す入口として
設定 `keywords`(カスタム語彙)が既にあるが、engine=haas のときだけ効いていた。Whisper が復号の文脈として受け取れるのは初期プロンプトだけ。
初期プロンプトは数える列の前置き(ここのつ、10。)と言い淀みのかなで、置き場所・末尾の 1 文字で他の発話の書き方が変わる(既存の ADR ドラフト)。

## 検討した選択肢

合成音声(transcriber-3 から数・四字熟語・感嘆・文頭の稀な語・言い淀み・速達の 7 本、語彙 1 語と 5 語)で比べた:

1. `{語彙}。ここのつ、10。えーと…えっと`(語彙を句点で閉じて前に置く) — 語彙 1 語で「…ここのつ、とお。」の「とお」が「等」に戻る(却下)
2. `ここのつ、10。{語彙}。えーと…えっと`(数と言い淀みの間) — 1 語は通るが、5 語で文頭の感嘆「ああ、」が落ちる(却下)
3. `ここのつ、10。えーと…まあ、{語彙}、えっと`(言い淀みの中) — 1 語は通る。末尾に近く、最初の語の当て方に効きやすい(採らない)
4. **`{語彙}、ここのつ、10。えーと…えっと`(語彙を読点で数える列の前に続ける)** — 1 語・5 語とも全部通る
5. 語の置換表・後処理で書き換える — 1 語ずつ塞ぐことになる(owner の統合で却下)

## 決定

4 を採る(`Decoding.PromptFor`。`WhisperTranscriber.Load` が設定 `keywords` を受け取る)。語彙が空なら初期プロンプトは今までと同じ文字列。
渡すのは表記だけで、`表記=よみ` の読みは渡さない(whisper は読みを受け取れない)。読めない語(Haas と同じ判定)は渡さず、どちらのエンジンでも通知する。
whisper.cpp はプロンプトが長すぎると先頭から捨てるので、語彙が多すぎても数・言い淀みの部分は残る(語彙の先頭から効かなくなる)。

## 結果

- 語彙に「速達」を書くと、既定の Whisper で「速達で送ってください」と届く(台本 transcriber-3 の最後の発話。語彙なしでは「即達」)
- transcriber-3 は語彙「速達」を入れた設定で回す(語彙を足しても他の発話の期待が変わらないことも確かめる)
- 設定画面・README・CONTEXT の「カスタム語彙」は、どちらのエンジンでも効く書き方にし、読みが効くのは Haas のときだけと書く
- 語彙を変えたら再起動で効く(Whisper の処理器は起動時に作る)
