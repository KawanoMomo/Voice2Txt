# ADR-draft: 文字起こし中に別アプリへ移っても元の入力欄に届ける — 届け方 return(前面を戻して貼り、クリップボードを戻す)

- **ステータス**: 提案(未採番)
- **カテゴリ**: architecture
- **日付**: 2026-11-02
- **対象プロジェクト**: Voice2Txt
- **関連**: BLK-human-20261102-1110-2、ADR-draft clipboard-busy-retry-and-delivery-failed、ADR-draft paste-settle-before-next-clipboard-write

## コンテキスト

離した時点で前面ウィンドウが押した時点と違うと、確定版は貼らずにクリップボードへ退避する。利用者は元の入力欄に戻ってクリックし Ctrl+V しないと入らず、
その間に自分が使っているクリップボードの中身が確定版で上書きされる。CPU で動く PC のように文字起こしに時間がかかるほど、待つ間に別のアプリへ移りやすい。

## 検討した選択肢

1. 押した時点のウィンドウを前面に戻して Ctrl+V で貼り、元の前面へ戻す。貼った後にクリップボードを元の中身へ戻す
2. 背後の入力欄へ直接文字を送る(WM_PASTE・UI Automation の ValuePattern)— 標準の Edit には効くが、ブラウザ・Electron では黙って何も起きず、届いたかを確かめられない(発話を黙って失う)
3. 届かなかった確定版をアプリ内の「未届けの一覧」に溜め、オーバーレイやトレイから選んで貼る — 新しい UI が要り、結局元の欄へ戻る操作が要る

## 決定

1 を設定 `delivery: return` として足す(既定は今までどおり evacuate)。前面に戻すのは UI スレッドで、今の前面と相手のスレッドの入力に一時的につないでから
SetForegroundWindow する(背後のアプリは前面を奪えない)。戻せたかは前面を確かめ、戻せなければ従来どおり退避する(確定版はクリップボードに残す。失わない)。
クリップボードは確定版を入れる前に形式ごとに写し、貼った後 0.5 秒(貼り付け先がクリップボードを読み終えるまで。PasteSettleMs)待ってから戻す。
その間に利用者がコピーした(クリップボードの通し番号が変わった)ら戻さない。離してから届くまでの時間には、戻すまでの待ちを含めない。

## 結果

- 前面を移す間(約 0.5 秒)、利用者のキー入力が貼り付け先へ入りうる。既定にしない理由の 1 つ。実機での確かめは人間の受け入れで行う
- 検証モードは仮の前面とメモリのクリップボードで確かめる(台本の `setClipboard`、期待の `clipboard` / `window`)。本物の SetForegroundWindow の効き方は検証モードでは確かめられない
