# ADR-draft: 途中経過は押下中の音声の写しを同じエンジンで頭から作り直し、オーバーレイにだけ出す

- **ステータス**: 提案(未採番)
- **カテゴリ**: architecture
- **日付**: 2026-10-07
- **対象プロジェクト**: Voice2Txt
- **関連**: 仕様 4.5(途中経過はオーバーレイにだけ)・7 章(途中経過のオーバーレイ表示、CPU / NPU では自動でオフ)・8 章(途中経過は後から変わる)、MOC 案 A、BLK-human-20261007-2004-1-wish

## コンテキスト

基盤ではエンジンの境界(`ITranscriber` の `IProgress<string> partial`)だけを用意し、押下中は「録音中」だけを出していた。
実機で、話している内容が拾えているかが押下中に分からないという要望が出た。仕様は「途中経過はオーバーレイにだけ出し、操作中のアプリには書き込まない」。
MOC は「約 0.7 秒ごとにそれまでの音声を頭から文字起こしし直す」案 A を描いている。エンジン(whisper.cpp)は 1 つで、確定版の文字起こしと共用する。

## 検討した選択肢

1. whisper.cpp のストリーミング(stream 例の短い窓のずらし)— 窓の境目で語が切れて前後が揃わず、確定版と見え方が大きく違う。Whisper.net に API が無い
2. `ITranscriber.partial` に復号中のセグメントを流す — 押下中はまだ音声が揃っておらず、離すまで復号を始められない(押下中に出せない)
3. 押下中、一定間隔で録音の写し(`IRecording.Snapshot`)を同じエンジンで頭から文字起こしし直し、結果をオーバーレイの状態(`OverlayView.Interim`)にだけ載せる(MOC 案 A)

## 決定

3 を採る。`PushToTalkController` が録音中になった発話ごとに作り直しの繰り返しを持ち、前の作り直しが終わってから `InterimIntervalMs`(既定 700 ms)空けて次を作る。
確定版を待たせないため、(a) 処理待ちの発話がある間は作らない、(b) 離す・取り消しで止める(進行中の復号は CancellationToken で止める)。
無音取り消しと同じしきい値で無音なら作らず、無音を詰めてから渡す(確定版と同じ前処理)。途中経過の失敗は録音にも確定版にも響かせない。
途中経過は届け方(クリップボード・Ctrl+V)の経路に一切載らない。離した後は、その発話の結末が出るまで最後の途中経過を「文字起こし中…」の下に残す(MOC の処理中)。
設定 `showInterim`(初期値オン)で切れる。CPU / NPU での自動オフは、バックエンドの自動選択(7 章)と一緒に入れる。

## 結果

- 確定版の経路・順序・届け方は変わらない。押下中のエンジン使用が増える(10 秒の発話で 0.9〜1 秒ごとに 1 回、1 回 0.2〜0.3 秒、CUDA)
- 進行中の作り直しが止まり切らない間に離すと、確定版がその残りだけ待つことがある(最大で作り直し 1 回分)
- オーバーレイは途中経過の分だけ縦に伸びる(最大 3 行、幅 520 px。収まらなければ頭を削って末尾を残す)
- 検証モードは途中経過の文字数を状態・shot ごとに結果へ残す(本文は書かない)。台本の期待は shot の `minInterimChars` / `maxInterimChars`
