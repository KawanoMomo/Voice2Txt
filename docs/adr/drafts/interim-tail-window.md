# ADR-draft: 長く話したときの途中経過は録音の末尾(約 25 秒)だけを文字起こしし直す

- **ステータス**: 提案(未採番)
- **カテゴリ**: architecture
- **日付**: 2026-11-04
- **対象プロジェクト**: Voice2Txt
- **関連**: interim-retranscribe-snapshot(途中経過は写しを頭から作り直す)、haas-long-utterance-regions-in-app、BLK-owner-20261104-0320-1

## コンテキスト

途中経過は押下中の音声の写しを毎回頭から文字起こししていた。押さない録音で 3 分話すと、1 回の作り直しが録音の長さに比例して重くなり
(whisper の拾い直しが 30 秒ごとに渡し直すので 1 回に decode-pass が 5〜6 本)、2 分半で出し直しの間隔が 11〜12 秒に延び、録音中ずっと GPU を占めた。
オーバーレイに出すのは末尾の 3 行(幅 520 px、約 100 字)だけで、頭の文字起こしは画面に出ない。

## 検討した選択肢

1. 今までどおり頭から(長くなるほど遅い)
2. 固定の秒数でちょうど切る — 語の途中で切れて頭の語が崩れる
3. 声の区間(`SpeechRegions.Find`、Haas の長い発話の区切りと同じ)のうち、末尾 25 秒に入る最初の区間の頭から渡す
4. 確定済みの頭の文字列を覚えておき、末尾だけを足す(ストリーミング) — 区間の境で前後が揃わず、確定版と見え方が違う

## 決定

3 を採る(`SpeechRegions.InterimStart`、`InterimTailSeconds = 25`)。区間は 10 秒までなので、続けて話していれば渡す長さは 15〜25 秒になり、
1 回で渡す長さ(`LongSeconds` 30 秒)を超えない(Haas の区間分け・whisper の渡し直しが途中経過で起きない)。頭を削った途中経過は「…」から始める。
確定版は今までどおり全体を文字起こしする。設定項目は増やさない。

## 結果

- 3 分の押さない録音(検証モード、CUDA)で、出し直しの間隔は録音の長さにかかわらず平均 1.2〜1.4 秒、途中経過に decode-pass が出ない
- 25 秒以下の発話の途中経過は変わらない
- 途中経過で拾い直した区間の再利用(`SpanCache`)は、末尾の窓と全体とで区間の切れ目が違えば効かないことがある(確定版の結果は変わらない)
