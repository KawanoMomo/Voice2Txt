# ADR-draft: 日本語の文字の間の空白は届ける直前に詰める(プロンプトでなく後処理)

- **ステータス**: 提案(未採番)
- **カテゴリ**: architecture
- **日付**: 2026-11-03
- **対象プロジェクト**: Voice2Txt
- **関連**: decoding-initial-prompt-no-final-period.md(末尾の句点を外した決定。その副作用)、remove-fillers-before-delivery.md(届ける前の後処理の先例)、BLK-owner-20261103-0635-1

## コンテキスト

初期プロンプトの末尾の句点を外してから、2 文以上の発話の確定版で句点の後に半角の空白が入るようになった(primary の m01〜m10 で 10 本中 4 本、5 周とも同じ)。
日本語の文の間に空白は入らず、貼った後に利用者が消して回る。`Decoding` の注記は「語の置換表・後処理ではない(届いた文字列は書き換えない)」としていた。

## 検討した選択肢

1. 初期プロンプトを直す — 前の ADR の比較で、句点で終わるプロンプトは中身に関係なく「一期一会」を「一期一への」にし、句点で終えない形は今の 1 つしか両立しなかった。空白だけを消す形を探すのは試行が多く、モデルが変われば崩れる
2. 区切り(whisper の segment)をつなぐ所で先頭の空白を落とす — 空白が区切りの中に書かれる場合を拾えず、Haas エンジンには効かない
3. **届ける直前に、日本語の文字と文字の間(と日本語の句読点と数字の間)の空白だけを詰める** — 語は置き換えない。英文の語の間・英文と日本語の境の空白は残す

## 決定

3 を採る。`Voice2Txt.Core.Spacing.Tidy` を `PushToTalkController` が言い淀みを取り除いた後に掛ける(確定版と途中経過の両方)。設定では止めない(日本語の文の間に空白を入れる利用者はいないため、設定項目を増やさない)。
初期プロンプトは変えない(「一期一会」と「…9つ、10。」を守る)。`Decoding` の「後処理ではない」は初期プロンプトの役目についての記述として残し、空白は後で詰めると注記する。

## 結果

- m01〜m10 で句点の後の空白が 0(unit `SpacingTests`、台本 `transcriber-3` の 2 文の発話 utt-15・utt-26・utt-32 に `notContains: [" "]`)
- 英文の語の間の空白、「booking.と」「、 Please」のような英文と日本語の境は変わらない
- 数字と漢字の間(「10 個」)の空白は英数字側の扱いとして残す
