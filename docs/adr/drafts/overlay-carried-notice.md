# ADR-draft: 録音中・処理中に起きた退避・入力失敗は、行の末尾に件数を出し、済んだ後にまとめて知らせる

- **ステータス**: 提案(未採番)
- **カテゴリ**: design
- **日付**: 2026-11-05
- **対象プロジェクト**: Voice2Txt
- **関連**: BLK-owner-20261104-2353-1、仕様 4.4(退避)・6 章の基準 3

## コンテキスト

退避・入力失敗の知らせは、確定版を届けた時点の一瞬だけの状態(`_transient`)として出していた。オーバーレイは押下中・処理待ちの状態を先に出すので、
次の発話を録音している間・処理待ちが残っている間に起きた退避・入力失敗は一度も出ず、続く貼り付けがクリップボードを上書きすると、
「Ctrl+V で貼れます」も成り立たなくなる(確定版が黙って欠ける)。

## 検討した選択肢

### A) 押下中の行の上に、知らせの行をもう 1 行出す
- メリット: 起きたその場で文言全体が見える
- デメリット: 途中経過の欄と並んで 3 段になり、配置(OverlayLayout・reviewer-2 の寸法)を作り直す。録音中に長い文を読ませる

### B) 録音・処理が済んだ後にだけ出す
- メリット: 配置を変えない。文言を後の貼り付けの結果(上書きしたか)に合わせられる
- デメリット: 連投が長いと、済むまで何も見えない

### C) B に加え、押下中・処理中の行の末尾に件数だけを注意の色で足す(採用)
- メリット: 起きたことはその場で分かり、詳しい文言と拾い方(Ctrl+V か Win+V か)は済んだ後に正しく言える。行は 1 段のまま
- デメリット: 済んだ後の知らせが貼り付け完了を置き換える(貼り付け完了は見落としても失うものが無いので、こちらを優先する)

## 決定

C。退避・入力失敗の件数と「最後に退避した確定版がまだクリップボードにあるか」を持ち越し、押下中でも処理待ちも無くなった時点で 1 つの知らせにする。
1 件で Ctrl+V で貼れるなら MOC の文言のまま。後の貼り付けで上書きした後は Win+V の履歴にあることを言う。届け方 return の貼り付けはクリップボードを戻すので上書きに数えない。
クリップボードを元に戻さない(仕様 4.4)・設定項目と画面を増やさないは変えない。
