# ADR-draft: オーバーレイの案内の行は一番下に固定し、途中経過はその上に積む

- **ステータス**: 提案(未採番)
- **カテゴリ**: ui
- **日付**: 2026-10-07
- **対象プロジェクト**: Voice2Txt
- **関連**: MOC `.partial`(本文の下に途中経過)、ADR-draft interim-retranscribe-snapshot、BLK-human-20261007-2229-2

## コンテキスト

オーバーレイは画面の下端からの距離を一定にして置き、途中経過の分だけ上へ伸びる。MOC と同じく案内の行(状態の印と本文)を上、途中経過を下に置いていたため、
途中経過の行数が増えるたびに案内の行(録音中の赤い点・「右 Ctrl を離すと入力」)が上へ動き、途中経過の幅が伸びて窓が広がるたびに左へも動いた。
実機で、常に出る案内が動いて読みにくいという所見が出た(人間の要望: 案内は一番下に固定、途中経過はその上)。

## 検討した選択肢

1. MOC どおり案内の行を上に置き、窓を上端基準で下へ伸ばす — 画面下端から離れた位置に出ることになり、伸びた窓が貼り付け先の入力欄に被る
2. 案内の行を窓の一番下に置き、途中経過を上に積む。窓の幅が変わっても案内の行の画面上の左端が変わらないよう、行を窓の中央に置く
3. 2 の縦だけを直し、行は窓の左寄せのまま — 途中経過が 1 行で伸びている間は窓の幅が変わり、案内の行が左右に動く

## 決定

2 を採る。配置の計算は `OverlayLayout`(Core)に置き、行の下端を窓の下端に合わせ、窓の下端は作業領域の下端から 18 px に固定する。
案内の行の画面上の左端は「途中経過の無い窓を画面中央に置いたとき」と同じ所にし、窓はそれに合わせて置く(端数の 1 px で窓が中央から外れることがある)。
途中経過と案内の行の間に区切り線を引く。途中経過の上限(3 行・幅 520 px、頭を削って末尾を残す)は変えない。

## 結果

- 途中経過の行数・幅によらず、案内の行は画面上で動かない。途中経過が無い窓の見た目は従来と同じ
- MOC と上下が逆になる(MOC の `.partial` は本文の下)。MOC は人間側の正本なので書き換えない
- 検証モードは shot ごとに途中経過の行数(`interimLines`)と案内の行の画面上の左上(`hintRowX` / `hintRowY`)を結果に残す。台本の期待は shot の
  `minInterimLines` / `maxInterimLines` / `sameHintRowAs`(別の shot と案内の行の位置が同じこと)
