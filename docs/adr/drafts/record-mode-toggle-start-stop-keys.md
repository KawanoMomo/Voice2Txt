# ADR-draft: 押さない録音は録音のしかたの設定で切り替え、開始キー・終了キーの判定を別のフィルタにする

- **ステータス**: 提案(未採番)
- **カテゴリ**: architecture
- **日付**: 2026-11-03
- **対象プロジェクト**: Voice2Txt
- **関連**: settings-screen-from-schema.md、BLK-human-20261103-1500-2(却下済みの BLK-junior-20261008-1004-wish を人間の決定で改めたもの)

## コンテキスト

録音はトークキーを押している間だけで、30 秒を超えて話すとき・画面を操作しながら話すときに指を離せない。人間の要望で、開始キーで録音を始め終了キーで止める「押さない録音」を、
今の「押している間だけ録音」を残したまま設定で切り替えられるようにする。録音中に他のキー・マウスを使っても録音は途切れない(押している間だけ録音では、他のキーは取り消し)。

## 検討した選択肢

1. トークキーの判定(`TalkKeyFilter`)にモードを足す — 押下中の他キーの取り消し・修飾キーとしての合成と、組み合わせの一致判定が 1 つの状態機械に混ざる
2. 両方のモードを同時に有効にする(トークキーも開始キーも常に効く) — 押さない録音の録音中にトークキーを押したときの意味(取り消し・2 本目)を決める必要があり、利用者が混乱する
3. **設定 `recordMode`(hold / toggle)で排他に切り替え、押さない録音は別のフィルタ `ToggleKeyFilter`(`ITalkKeyFilter`)にする** — 制御(`PushToTalkController`)には押下・離しと同じ合図(TalkDown / TalkUp)を渡すので、録音・処理・届け方・順序は共通

## 決定

3 を採る。開始キー・終了キーは修飾(Ctrl / Alt / Shift / Win)と 1 つのキーの組み合わせ(`KeyChord`。初期値どちらも Ctrl+Alt+Space で、同じなら押すたびに切り替わる)。
文字・数字・Space などは Ctrl / Alt / Win のどれかと組み合わせなければ読まない(ふつうの入力とぶつからない)。組み合わせの最後のキーだけを握りつぶし、修飾キーと他のキーはすべて素通しする。
修飾は過不足なく一致したときだけ。押さない録音の間、トークキーは録音に使わずアプリへ渡す。モデル準備中に開始キーを押したら録音せず、離したときと同じ知らせを出して、次の開始キーをもう一度開始として受ける。
キーボードフックだけを使い、マウスのフックは入れない(マウス操作は録音に関係しない)。設定の変更は他の項目と同じく再起動で効く。

## 結果

- 台本 `junior-5` に、設定画面で押さない録音を選んで再起動し、開始キー → 20 秒の間に文字・ショートカット・Tab・右 Ctrl・窓の切り替え → 終了キーで 1 本の確定版が届く流れを足した(素通ししたキーの列も期待に書く)
- オーバーレイの録音中の案内は「Ctrl+Alt+Space で入力」(押している間だけ録音は今のまま「右Ctrl を離すと入力」)
- 押さない録音の録音を取り消す専用の操作は無い(終了キーで止め、言い淀みだけ・無音なら取り消しになる)。要るなら別の課題
