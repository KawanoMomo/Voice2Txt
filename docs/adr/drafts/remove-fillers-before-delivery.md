# ADR-draft: 言い淀みは届ける直前に確定版から取り除く(区切りで判定する後処理)

- **ステータス**: 提案(未採番)
- **カテゴリ**: architecture
- **日付**: 2026-10-07
- **対象プロジェクト**: Voice2Txt
- **関連**: 仕様 7 章(句読点・表記の後処理、ユーザー辞書は後続)、`decoding-initial-prompt-fillers.md`、BLK-human-20261007-2004-2-wish

## コンテキスト

実機で「ええ」「ああ」「えっと」などの言い淀みがそのまま確定版に入り、利用者が貼った後に手で消している。
復号の初期プロンプト(`Decoding.InitialPrompt`)は言い淀みをかなで書かせるためのもので、言い淀みはかなのまま確定版に残る。
取り除く語の多く(「あの」「その」「まあ」「ええ」「ああ」)は、指示語・返事・副詞と同じ形をしている(「あの人」「そのため」「ああいう」)。

## 検討した選択肢

1. 初期プロンプトから言い淀みを外す・言い淀みの無い文を見せる — Whisper が言い淀みを英字や別の語に当てる化けが戻る(前の ADR の理由)。消えるかどうかもモデル任せで、設定で止められない
2. 語の単純な置換(全出現を消す)— 「あの人」「そのため」「その一方で」を壊す
3. **区切りで判定する後処理**: 語が区切り(文頭・句読点・空白)から始まる所だけを消す。2 文字の語は後ろも区切りのときだけ、3 文字以上の語(「ええと」「えっと」「うーん」)は後ろに語が続いても消す。語の後ろの伸ばしと読点は一緒に消し、跡の「、。」・文頭の読点を整える
4. 形態素解析(感動詞の品詞で判定)— 依存(辞書)が大きく、Whisper の句読点の付け方の方が判定の手掛かりとして安定している

## 決定

3 を採る。`Voice2Txt.Core.Fillers.Remove` を `PushToTalkController` が文字起こしの直後・届ける前に 1 回掛ける。
設定 `removeFillers`(初期値 true)で止められ、語は `fillers`(初期値 `Fillers.DefaultWords`)で変えられる。初期プロンプトはそのまま残す(化けを防ぐ役目は変わらない)。
言い淀みだけの発話は空になり、取り消し(NoText、「取り消し(無音)」)になる。取り除いた数は結果・ログに `fillers=` で残す(本文は残さない)。

## 結果

- utt-12(「ええと」2 回)と utt-17(「ええ」「あの」「えっと」)で言い淀みが残らず、他の語は残る(scenario `transcriber-3`、unit `FillersTests`)
- 句読点を付けずに書かれた 2 文字の言い淀み(「あの資料」の「あの」が言い淀みだった場合)は残る。誤って文の語を消すより残す側に倒した
- transcriber の corpus の正解文は言い淀みを含む(redo-02 など)。届く確定版には言い淀みが無いので、正解文との突き合わせは言い淀みを除いて比べる
