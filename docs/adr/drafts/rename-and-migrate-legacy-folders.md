# ADR-draft: 製品名を Voice2Txt にし、旧名の置き場は通常起動の最初に移す

- **ステータス**: 提案(未採番)
- **カテゴリ**: architecture
- **日付**: 2026-10-07
- **対象プロジェクト**: Voice2Txt
- **関連**: BLK-human-20261007-2120-1

## コンテキスト

旧名の接頭辞は管理情報なので公開物に含めない(リポジトリの `git grep -i` で 0 件)。一方、利用中の PC には旧名の置き場(`%APPDATA%` の設定・モデル・ログ、
`%LOCALAPPDATA%` の CUDA の実行時ライブラリ)と HKCU の Run の旧名の値が残っており、改名した版がそれを引き継がないと設定が初期値に戻り、モデル(1.6 GB)を取り直し、旧版が自動起動し続ける。

## 検討した選択肢

1. 旧名の置き場を読み続ける — 公開物に旧名が残り続ける
2. 旧名の置き場を写す(コピー) — モデルと実行時ライブラリで 2 GB 超を重複させる
3. **通常起動の最初に移す(同じドライブなのでフォルダの付け替え。新しい側が既にあれば 1 ファイルずつ、無いものだけ)** — 重複しない。使用中で移せないものは旧側に残し、起動は止めない

## 決定

3 を採る。新しい側に同じ名前のファイルがあれば新しい方を残す(同じ大きさ・更新時刻なら同じものとして旧い方を消す)。Run の旧名の値は外し、`autoStart` に従って新しい名前で登録し直す。
旧名の版が動いている間は起動しない(トークキーを二つが奪い合うため)。検証モードは利用者の置き場に触れない。旧名の文字列は接頭辞と製品名の連結で作り(`LegacyName.Name`)、リポジトリに旧名をそのまま書かない。

## 結果

移した数・残した数・失敗数をログ `legacy-migrated` に 1 行書く。ロジックは `LegacyName`(Core)で unit が守る。
