# ADR-draft: 設定画面は Core の項目表から作り、保存は settings.json、効くのは再起動から

- **ステータス**: 提案(未採番)
- **カテゴリ**: architecture
- **日付**: 2026-10-07
- **対象プロジェクト**: Voice2Txt
- **関連**: 仕様 5 章 7(最小限の設定)、BLK-human-20261007-2024-1-wish

## コンテキスト

設定はトレイの「設定ファイルを開く」で JSON を手で直すだけで、項目が増えるとキー名と取れる値が分からない。
検証モードは GUI へのクリックが届かないので、画面を作っても台本から確かめられる形にしないと受け入れ条件(画面で右 Alt に変えて保存し、再起動後に右 Alt で録音できる)を守れない。

## 検討した選択肢

1. 画面ごとに部品と検証を手で書く — 項目を足すたびに画面・検証・説明がずれる
2. **Core に項目表(`SettingsSchema`: キー・名前・説明・種類・選択肢・範囲)と値の移し方(`Apply` / `Read`)を置き、画面はそこから部品を並べる** — 画面と台本(setSetting)が同じ規則を通る。unit で項目表と settings.json のキーが一致することを守れる
3. 保存した値をその場で効かせる(トークキーのフック・モデルを差し替える)— フックとモデルの作り直しを動作中に行う経路が増える。基盤は「変更は再起動で効く」と決めている

## 決定

2 を採り、保存先は今の settings.json(手書きも残す)。効くのは再起動から(自動起動だけは保存時に登録を合わせる)。保存後に「今すぐ再起動」を選べ、選ぶと排他を手放してから自分を起動し直す。
検証モードは本物の `SettingsForm` を開き、`SetValue` / `ClickSave` で部品を操作し、`restart` で保存した settings.json を読み直す(トークキー・設定・モデルが変われば読み込みも)。設定画面のスクショは自前の描画(DrawToBitmap)で撮る。

## 結果

- scenario `junior-5` が画面での変更 → 保存 → 再起動 → 右 Alt で録音を通しで確かめる
- 項目を足すときは `AppSettings` と `SettingsSchema.Items` の両方に足す(unit「設定ファイルの全項目が画面に名前と説明付きで並ぶ」が漏れを赤にする)
- トークキーの選択肢は単独で押しても紛れにくいキーに限る。手で書いた選択肢外の値は「(設定ファイルの値)」として残せる
