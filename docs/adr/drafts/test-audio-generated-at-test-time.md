# ADR-draft: テストの音声素材はリポジトリに入れず、テスト実行時に音声合成で作る

- **ステータス**: 提案(未採番)
- **カテゴリ**: process
- **日付**: 2026-10-07
- **対象プロジェクト**: Voice2Txt
- **関連**: BLK-human-20261007-2050-1(公開の前提)、`THIRD_PARTY_NOTICES.md`

## コンテキスト

検証モードの台本は `tests/fixtures/audio/*.wav`(Windows の音声合成で作った日本語の文)を Git で管理していた。
リポジトリを公開する方針になり、音声合成の声(Microsoft の音声)で作った音声を公開リポジトリに含めない、`git ls-files` にバイナリを残さない、と決めた。
台本と unit は素材の無い clone から通らなければならない。

## 検討した選択肢

1. Git LFS や別のリポジトリに置く — 公開の場所が変わるだけで、合成音声を配ることは変わらない
2. 素材を使わない(台本の音声をトーンや雑音に替える)— 文字起こしの確定版・順序・言い淀み・途中経過を確かめられない
3. テスト実行時に、同じ文を同じ声で合成して `test-results/fixtures/` に作る(作り方はコード、素材は作るたびに手元だけ)

## 決定

3 を採る。`tools/MakeFixtures`(System.Speech、日本語の声)が文・前後の無音・小さい声の加工を持ち、足りない素材だけを作る。
`tools/Verify` は台本を回す前に同じ手順で作る。台本の `audio` は `test-results/fixtures/` を指す。これまでの `make-fixtures.ps1` は C# に移して消す。
同じ PC・同じ声なら作った素材は以前の Git 管理の素材とバイト単位で一致した(20 本すべて)。

## 結果

- 素材の無い clone でも `dotnet test` は通り、`tools/Verify` は初回に約 20 本を作ってから回す(数秒)
- 日本語の音声合成の声(Windows の「音声」の日本語)が入っていない PC では素材を作れない(MakeFixtures がその旨を出す)
- 声の版が変わると素材が変わりうる。そのときは `--force` で作り直し、合成の読みと台本の期待を見直す
