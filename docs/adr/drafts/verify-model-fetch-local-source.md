# ADR-draft: 検証モードでモデルの取得中の表示を確かめる — 取得元を手元のファイルに差し替える

- **ステータス**: 提案(未採番)
- **カテゴリ**: testing
- **日付**: 2026-10-08
- **対象プロジェクト**: Voice2Txt
- **関連**: BLK-primary-20261007-2155、ADR-draft foundation-backend-fallback-and-verify-boundaries

## コンテキスト

モデルの準備中、常駐時はトレイのツールチップとオーバーレイが「モデル準備中 ダウンロード n%」→「読み込み」→「暖機」と変わる。
検証モードはこの段階をオーバーレイへ渡すだけで記録せず、取得済みのモデルでは取得の段階そのものが起きないので、
大きいモデルを選んだ利用者が待つ間に何を見るかを確かめられなかった。

## 検討した選択肢

1. 空のモデルのフォルダで台本を回し、本物の取得元(Hugging Face)から取る — 台本ごとに数百 MB〜3 GB を取得し、回線で結果と時間が揺れる。releaser が 4 時間ごとに全部回すのに向かない
2. 検証済みの印を消して「検証」の段階から始める — 共用のモデルのフォルダを書き換える。取得の段階は確かめられない
3. 取得元だけを手元のファイルに差し替える(`HttpMessageHandler`)。`ModelProvisioner` のダウンロード・ハッシュ照合・進み具合の経路は本物のまま通し、決めた時間をかけて少しずつ返す

## 決定

3 を採る。台本の `modelPrep: "download"` で、モデルのフォルダを `<out>/models`(空)にし、手元のモデルのフォルダの同じファイルを
`modelFetchMs` かけて返す。手元にも無ければ先に本物の取得元から手元へ取る。取得したモデルの複製は終わったら消す。
準備の段階は、段階が変わるたびと進み具合が 10% の刻みを跨ぐたびに、そのときのトレイのツールチップと一緒に result.json の `modelPrep` と verify.log に残す。
画面(トレイ・オーバーレイ)は 1% ごとのまま。準備中に押したときのオーバーレイの記録・スクショも同じ刻みにする。

## 結果

- 台本で準備中に press すれば「モデル準備中(ダウンロード n%)」のスクショが撮れ、期待 `modelPrep`(段階の列)で確かめられる
- 回線の速さ・取得元の不調による表示(遅い・止まる)は確かめられない(実機受け入れの範囲)
- 進み具合の報告を後から UI スレッドへ投げていたため、取得の最後の「100%」が「読み込み」の後に届いて表示が前の段階に戻っていた。報告はその場で渡す(`InlineProgress`)
