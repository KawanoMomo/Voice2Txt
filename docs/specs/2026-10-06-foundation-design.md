## 1. 目的

Claude Code のスペース長押し音声入力と同じ体験を、Claude Code 以外のアプリでも使えるようにする。
ローカルの Whisper だけで文字起こしし、音声を外部へ送らない。

中核のユースケースは**プッシュトゥトーク音声入力**。**ファイル文字起こし**は、同じエンジンを使う2つ目の入口として後続ループで足す。

本書は、ループ開発の起点となる「基盤(ループ0)」の範囲と、後続ループが前提にしてよい決定事項を定める。

## 2. 対象環境

| 区分 | 機種 | 扱い |
|---|---|---|
| 正式対象 | このPC(RTX 2080 Ti、Windows 11) | 基盤で対応し、実機受け入れを行う |
| 正式対象 | Intel Core Ultra ノート(iGPU / NPU) | 後続ループで対応し、追加時に実機受け入れを行う |
| **ベストエフォート機種** | 上記以外(AMD GPU、NPU無しの機種など) | Vulkan か CPU で動けば良し。検証しない |
| 対象外 | AMD Ryzen AI・Qualcomm の NPU | 扱わない |

OS は Windows 11 のみ。

## 3. 技術選定(ADRドラフトあり)

- **文字起こしエンジン**: whisper.cpp に一本化する。バックエンドは CUDA / Vulkan / CPU。Intel NPU は OpenVINO 経由とし、後続ループで扱う
- **常駐アプリ本体**: C# / .NET。whisper.cpp は Whisper.net を使い、プロセス内に取り込む
- **初期モデル**: `large-v3-turbo`
- 各バックエンドで実際に何が動くか(特に OpenVINO で NPU に載る範囲)は未実測。実機で確定させる

## 4. 振る舞い(基盤で確定するルール)

### 4.1 トークキー

- 単独の専用キー。初期値は右 Ctrl。設定で変更できる
- 押したキーは握りつぶし、操作中のアプリへ渡さない
- トークキーを押している間に別のキーが押されたら、その発話は**取り消し**とする。代わりに修飾キーとして押されたことにして、ショートカット(例: 右 Ctrl+C)を通常どおり効かせる
- 押下が短すぎる場合(初期値 0.3秒未満、設定値)は**取り消し**とする

### 4.2 録音

- マイクは、トークキーを押した瞬間に Windows 既定の録音デバイスを開く。常時は開かない
- マイクが開くまでは、オーバーレイに「準備中」を出す。実際に録音が始まった瞬間に「録音中」へ切り替える(赤い点が出てから話す運用)
- 録音した音声の音量が閾値を下回る(無音)場合は、Whisper に渡さず**取り消し**とし、オーバーレイに「音声が検出されませんでした」と出す。閾値は設定値で、初期値は実機で調整する

### 4.3 発話の処理順

- 処理中でもトークキーを受け付け、次の**発話**を録音する
- 発話は録音した順に処理し、その順で届ける。後の発話が先に終わっても、追い越させない

### 4.4 届け方

- 結果は**確定版**だけを届ける。確定版は、トークキーを離した時点で発話の音声全体を文字起こしし直したもの
- 確定版をクリップボードに入れ、Ctrl+V を送って貼り付ける
- クリップボードは元の内容に戻さない。元の内容は Windows のクリップボード履歴(Win+V)から取り出す運用とする(**前提: クリップボード履歴が有効**。ツールから有効化を促すことはしない)
- 貼り付け時点で前面にあるウィンドウが**貼り付け先ウィンドウ**と一致する場合だけ貼る。一致しない場合は**退避**する。判定はウィンドウハンドル単位とし、同じウィンドウ内での入力欄の移動は追わない
- **退避**: Ctrl+V を送らず、確定版をクリップボードに残し、オーバーレイで「Ctrl+V で貼れます」と知らせる

### 4.5 表示

- **オーバーレイ**を画面下中央に出す。フォーカスを奪わない・クリックを素通りさせる・常に最前面、を必須要件とする(フォーカスを奪うと、貼り付け先ウィンドウの判定が崩れて毎回退避になるため)
- 状態は「準備中/録音中/処理中/処理中+次を録音中(処理待ち件数)/貼り付け完了/退避/取り消し(無音)/モデル準備中」。見た目は MOC に従う
- トレイアイコンは補助表示とし、状態に応じて変化させる
- **途中経過**はオーバーレイにだけ出し、操作中のアプリには書き込まない(後続ループで実装。基盤ではエンジンの境界だけ用意する)

### 4.6 モデルの用意

- 初回起動時に、固定の取得元(whisper.cpp の公式モデル)からダウンロードし、ハッシュで検証してから使う
- 決まったフォルダへの手動配置も受け付ける
- 準備が終わるまでは、トレイで進み具合を示す。トークキーが押されたら、オーバーレイに「モデル準備中」と出す
- ネットに出るのはモデル取得のときだけ。文字起こしは完全にローカルで行う

## 5. 基盤(ループ0)の範囲

**ゴール: このPC上で、プッシュトゥトーク音声入力が最初から最後まで通ること**

含めるもの:

1. タスクトレイ常駐。起動時にモデルを読み込み、常駐させる
2. トークキーによる録音の開始・終了(4.1、4.2)
3. 発話の順番どおりの処理(4.3)
4. 確定版の貼り付けと退避(4.4)
5. オーバーレイとトレイアイコン(4.5、途中経過を除く)
6. モデルの用意(4.6)
7. 最小限の設定: トークキー、モデルの選択
8. 言語は日本語固定、バックエンドは CUDA 固定
9. 境界だけ先に切っておくもの: エンジン(途中経過も返せる形)、バックエンド選択、届け方
10. **検証モード**(第6章)

## 6. 検証方針

- 中核のロジック(発話の順序、取り消し、貼り付け先ウィンドウの判定、退避)は、キー・マイク・クリップボード・前面ウィンドウを差し替え可能にし、自動テストする
- **検証モード**: 起動オプションで、マイクの代わりに音声ファイルを流し込み、トークキーの押下・離しを外部から指示できるようにする。結果はアプリ自身が開く検証用のテキスト欄へ届け、オーバーレイのスクリーンショットを自動で撮る
- GUI(オーバーレイ・トレイ)の変化は、実機のスクリーンショットなしに PASS としない
- **実機受け入れ**(本物のマイク、他のアプリへの貼り付け)は、ユーザー本人が節目ごとに行う。対象は基盤の完成時と、対象機種を追加したとき
- 既存の evaluator(Playwright 前提)は Web アプリ向けのため、本ツールには使わない。この環境では GUI へのクリック・キー入力が届かないため、自動確認は検証モード経由で行う

### 基盤の受け入れ基準

- このPCの実機で、チャットアプリ・ブラウザ・エディタのそれぞれに、日本語の発話が確定版として貼り付けられる
- 処理中に次の発話を録音しても、どちらも失われず、録音した順で届く
- 処理中にウィンドウを切り替えると退避になり、Ctrl+V で貼れる
- 右 Ctrl+C が通常どおり効き、そのとき録音されない
- 無音で押して離しても、何も貼られない
- オーバーレイ表示中も、入力中のアプリからフォーカスが外れない
- 実測して記録する: トークキーを離してから貼り付けまでの時間、マイクが開くまでの時間

## 7. 後続ループの候補(順不同、着手順は別途決める)

- 途中経過のオーバーレイ表示(最初の候補)
- バックエンドの自動選択(CUDA → Vulkan → CPU)と、ユーザー設定による上書き。CPU / NPU では途中経過を自動でオフにする
- Intel Core Ultra 実機への対応、Intel NPU(OpenVINO)
- アプリごとの貼り付けキーの上書き(ターミナル向けの Ctrl+Shift+V 対策)
- 管理者権限ウィンドウへの対応(貼れないため、退避する)
- 録音の長さの上限、無音部分のトリミング
- 幻聴テキストの除外リスト(実際に使って集めた事例から作る)
- 句読点・表記の後処理、ユーザー辞書
- 効果音(オン・オフの設定付き)
- マイクを常時開く方式(設定で選択、押す少し前の音声も含める)
- オーバーレイの表示位置の選択肢(入力カーソルの近く)
- 録音デバイスの個別指定
- ファイル文字起こし

## 8. 既知の制約

- 管理者権限で動いているウィンドウには貼り付けられない(Windows の仕様)
- クリップボード履歴が無効な環境では、音声入力のたびに元のクリップボードの内容が失われる
- 途中経過は、後から聞こえた音声によって前の部分が変わることがある

## 9. QAログ(推奨案で先行決定した非クリティカル論点)

| 論点 | 決定 |

| 英単語が混じる発話 | Whisper にそのまま任せる。用語辞書は後続ループ |
| 録音の長さの上限 | 基盤では設けない |
